# Task 27 Second Draft Package

This folder contains the **second-draft implementation** of **Task 27: Build the App & Delivery response adapter and example response package**.

This revision incorporates review feedback from the initial draft, including consistent sanitisation of `gate_result` and `confidence_flag`, migration of the test suite to `pytest`, and relocation of the adapter tests to the repository-level `tests/` folder.

## Location

The Task 27 implementation and documentation live under `results/app_response/`. Example JSON outputs produced from the response adapter flow are kept in `results/app_response/examples/`, while the automated adapter test file lives in the repository level `tests/` folder.

## Included deliverables

- `results/app_response/app_response_adapter.py` — response adapter, structural validation, and UTF-8 JSON writer.
- `tests/test_app_response_adapter.py` — pytest tests for adapter behaviour including success, fallback, non-optimal, invalid input, sanitisation, structure, and non-mutation.
- `results/app_response/examples/success_response.json` — example `LLM_VALIDATED` adapter output.
- `results/app_response/examples/fallback_response.json` — example `TEMPLATE_FALLBACK` adapter output.
- `results/app_response/examples/error_response.json` — example non-optimal `STATUS_ONLY` adapter output.
- `results/app_response/examples/invalid_input_response.json` — example `INVALID_INPUT` adapter output.
- `results/app_response/App_Integration_Contract.md` — documented response contract, enums, warnings, stable/draft fields, and integration notes.

## Current draft boundary

Tasks 19, 21, 23, 25 and 26 are not final yet. Their values are therefore supplied to the adapter as upstream inputs rather than being reimplemented here. This allows App & Delivery to build against one outer response shape while the internal upstream payloads are finalised separately.

The JSON files in `results/app_response/examples/` are retained as example outputs of the adapter after representative upstream values are supplied. They are not generated by the test suite; the tests validate that these stored examples still conform to the current response contract.

## Changes from the first draft

The second draft incorporates the following review updates:

- Applied `_non_empty_text()` to `gate_result` and `confidence_flag` in the non-optimal `STATUS_ONLY` branch for consistency with the `OPTIMAL` branch.
- Converted `test_app_response_adapter.py` from `unittest` to `pytest`.
- Moved `test_app_response_adapter.py` to the repository-level `tests/` folder.
- Updated the test paths so the stored example responses remain under `results/app_response/examples/`.
- Added direct test coverage for trimming and blank-value sanitisation in non-optimal responses.

## Run tests

From the repository root:

```bash
python -m pytest -v tests/test_app_response_adapter.py
```
